## Why

The homepage names credible work, but deep evaluation remains uneven: only two projects have case studies, the portfolio has no project screenshots or explanatory diagrams, and evidence governance is not yet enforced as a publishing contract. The proof layer must let hiring managers inspect ownership and engineering judgment without exposing confidential information or overstating outcomes.

## What Changes

- Establish one consistent case-study system for orientation, attribution, problem, ownership, constraints, consequential decisions, system behavior, evidence, limitations, outcome, and next action.
- Add a CravingsPH case study focused on transaction consistency, concurrent operations, real-time workflows, lifecycle modeling, and security boundaries.
- Add one meaningful, responsive screenshot or explanatory system diagram to each featured project, using diagrams when screenshots are unavailable or unsafe.
- Extend project and case-study data with typed visual-artifact metadata rather than hard-coding media into page markup.
- Enforce source-backed claims, correct employer attribution, review dates, explicit limitations, screenshot sanitization, and withholding of unverified metrics.
- Preserve static publishing, metadata, structured data, social previews, sitemap coverage, semantic document structure, and useful internal navigation for every case study.

## Capabilities

### New Capabilities

- `case-study-system`: A reusable deep-evaluation structure, orientation model, next-action pattern, and completeness requirements for every published case study.
- `visual-proof-artifacts`: Typed, responsive, accessible, performant, and context-bearing screenshots or system diagrams for featured work.
- `evidence-governance`: Source traceability, attribution, confidentiality, sanitization, review-state, and claim-quality rules for public portfolio evidence.
- `case-study-discoverability`: Static route publication, metadata, structured data, social preview, sitemap, semantics, and internal-link requirements for case studies.

### Modified Capabilities

None. The repository has no archived main OpenSpec capabilities for case-study publishing or evidence governance.

## Impact

- Affects case-study records and types, the dynamic work route, project data, homepage project presentation, public media assets, Open Graph generation, sitemap generation, and portfolio governance references.
- Adds a new statically generated `/work/cravingsph` route and visual artifacts for Ample News, KudosCourts, and CravingsPH.
- Must be applied after or reconciled with `overhaul-portfolio-hiring-journey` because both changes touch featured-project presentation and data contracts.
- Does not add analytics, a CMS, visitor uploads, dynamic personalization, a writing archive, or programmatic SEO pages.
